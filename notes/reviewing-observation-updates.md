# 観測更新のレビュー

状態: **オフラインの比較・検算を実装**。この機能を追加するための新しいタイル取得は行っていません。

新しい観測を既存のノートへ反映する前に、行の差と、地点・ズーム・欠測・入力の版を確認するための補助コマンドです。CSVの比較と原本コピーを一つの観測更新手順にまとめています。Python標準ライブラリだけを使い、地理院サーバや外部APIへ接続しません。

## 実行

二種類の観測が完了し、書き込みが止まったフォルダ同士を指定します。

```sh
python3 scripts/review_observations.py \
  --before data/observations --after work/observations/new-run \
  --out work/reviews/new-run
python3 scripts/review_observations.py --verify work/reviews/new-run
```

| 終了コード | 意味 |
|---|---|
| 0 | 行・メタデータの内容に差なし。または `--verify` が成功 |
| 1 | 比較と検算が完了し、行またはメタデータの内容に差あり |
| 2 | 入力不備・既存の出力先・検算不一致・書き込み失敗など |

更新があると1で終了するため、その直後に `&&` で別の処理をつなぐ場合は注意してください。1は比較結果としての差を表し、実行失敗ではありません。

## 保存物

```text
work/reviews/new-run/
  inputs/before/            比較した元のCSV二つとメタデータ二つ
  inputs/after/             比較した新しいCSV二つとメタデータ二つ
  review.json              全件差分・件数合計・入力SHA-256・検算方法
  review.md                読むための概要（行明細は種類ごとに先頭20件）
```

入力は読み取ったバイト列のままコピーし、コピーした入力からもう一度検算します。元フォルダを削除しても、保存したレビューだけで `--verify` を実行できます。比較元のパスやフォルダ名はJSONに記録しません。`reviewer_sha256` は比較スクリプトの内容識別用で、過去の観測スクリプトの版を表すものではありません。

出力フォルダは新規作成だけを許可します。JSONは最後に書き、検算が成功したときだけ完了を表示します。途中でI/Oエラーになった場合は不完全なフォルダが残ることがあるため、別の出力先でやり直してください。電源断に対する永続性や複数ファイルのトランザクションは保証しません。

## 比較条件

| 対象 | 行のキー | 検算する件数列 |
|---|---|---|
| vector_tiles.csv | zoom / layer / vt_code | features / tiles |
| dem_png.csv | point / zoom / x / y | pixels / valid / nodata / below_sea_level |

キーと値は文字列の完全一致です。行順・列順の変更だけでは行の差にしませんが、入力バイト列のハッシュは変わります。UTF-8（BOMも可）を読み、数値列は非負整数だけを受け付けます。DEMの欠測行で空欄になっている件数は合計への寄与を0とし、空欄数を別に記録します。空欄と文字列 `0` の変更は行の差として残ります。高さの最小・最大などは合計せず、文字列として比較します。

重複キー、欠けた列・未知の列、壊れた行、不正な件数値はエラーです。vector_tilesの空のvt_codeは既存の観測形式なので許可します。将来CSVの列を変更する場合は、このコマンドのスキーマとテストも更新してください。

件数列の値はPython整数で合計し、浮動小数点へ変換しません。ただし列の単純合計であり、同じタイルや地物がズーム間・行間で重複することがあります。全タイル数、地物の全国総数、地域の統計値として扱わないでください。

## 検算の範囲

通常の差分はキーから行を引く辞書で求めます。検算ではコピーした入力を読み直し、キー順に並べた行を順番に突き合わせます。表示を省略した行を含め、追加・削除・変更・不変と全明細を照合します。件数合計も別の集計処理で再計算し、前後差が「追加分 − 削除分 ＋ 既存行の増減」と一致することを確認します。保存済みレビューの検算では、入力のハッシュ、JSONのチェックサム、読みやすい概要の内容も確認します。

二つの処理はCSVの読み取り・入力検証とPythonの整数演算を共有しています。検算は、選んだキーや観測方法そのものの妥当性を判定するものではありません。

メタデータの全フィールドについて変更を記録します。そのうち `source`・`points`・`zooms`・`linear_factors`・`tiles_observed`・`tiles_missing` は、記録された条件の差として概要にも表示します。`checked_at`、ETag、Last-Modified、入力ハッシュなどはJSONで確認できます。列挙したフィールドに差がなくても、記録されていない手順まで同一とは限りません。行の差をタイルの更新だけに帰属させないでください。

## 制限

- 対象は既存のCSV二種類とそのメタデータです。仕様書との照合結果や生のタイル・PMTiles・仕様書本体を保存する機能ではありません。
- 入力は完了済みで安定したフォルダを使ってください。複数ファイルの取得中・書き込み中に、一時点の整合したスナップショットを作る機能ではありません。
- 小規模な観測CSV向けにメモリ内で比較します。入力ファイルは一つ16MiBまでです。大規模CSV向けの外部ソートや性能改善は対象外です。
- ハッシュは偶発的な編集を検出する識別情報です。入力と証跡をすべて書き換えられる相手への防御や、取得元・取得日時の真正性は証明しません。
- `inputs/` には元のCSVとメタデータの内容が入ります。メタデータのURLや列の値も残るので、共有前に内容を確認してください。レビューは `work/` に置き、タイル・仕様書本体をGitへ加えない既存方針を維持します。

テストは架空のCSVによる追加・削除・変更、404から200への変化、浮動小数点で正確に表せない大きな整数、重複キー、壊れたメタデータ、保存物の改変を検証します。通常側の行比較と集計へ意図的な誤りを入れ、検算が拒否することも確認します。既存の観測CSVを同じもの同士で比較する確認は、新しい観測結果を得たことやタイルが変化していないことを意味しません。
